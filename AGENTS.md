# Notes for coding agents

Bounder is a side-scrolling platformer campaign (four worlds of four levels
and a fortress on overworld maps, then the final castle) built on GameLib
(https://github.com/alonohana627/GameLib, locally `C:\Users\user\GameLib`; a
separate repository). It is the second platformer of GameLib's run
(`GameLib/GAME_SUGGESTIONS/06-bounder.md` is its spec).

## Ground rules

- Consume GameLib only through its CMake targets (`GameLib::core`,
  `GameLib::app`, ...) and public headers (`<gamelib/...>`). Never copy GameLib
  sources into this repository or include its `src/` files. Use what GameLib
  offers (its `FEATURES.md` at the pinned commit) instead of rewriting it.
- GameLib is pinned by full commit hash in `CMakeLists.txt` (`GIT_TAG`,
  `GIT_SHALLOW FALSE`). Bump it only together with a row in
  `docs/GAMELIB_REVISION.md`. GameLib keeps no backwards compatibility.
- GameLib is changed only to fix a bug that blocks the game (GameLib commit
  with a headless test first, then a re-pin). Generic code the game had to
  write itself is kept separable and reported as a P0 candidate for GameLib's
  `FEATURE_SUGGESTIONS.md`; this repository has no feature-suggestions file.
- Snake, Tetris, Pong, Breakout, Asteroids, Invaders, Minesweeper and Leap are
  read-only references.
- Every visual is generated by shaders (GameLib's built-in shapes or this
  game's `shaders/`). No image files. Every sound and the music are
  synthesized with GameLib's synth.
- `src/game` (levels, rules, the session, the overworld, the demo bot) links
  only `GameLib::core`: no window, GPU, audio or clock; deterministic for the
  per-tick input. Presentation, menus, sounds and saves live in `src/app`.
- **Games have no tests**: no unit tests, no test executables, no
  `GameLib::testing`. The only CTest entry is the template's smoke run
  (`--hidden --require-validation --frames 120`), which enforces zero Vulkan
  validation messages on the title screen.
- Zero compiler warnings, zero shader warnings (glslc `-Werror`), zero
  validation messages.
- Small Conventional Commits (`feat(game):`, `feat(app):`, `fix:`, `build:`,
  `docs:`) after each step that builds and runs. Stage files explicitly;
  never commit build output. Never rewrite history. Push `main` to origin
  after each commit.
- `FEATURES.md` lists what the game does today, verified by running it;
  update it in the same commit as each feature; never list planned work.
- Run the game and look at it after every visual change (GameLib's
  self-test switches plus the `win32-game-window-automation` skill for
  screenshots). Do not drive F11 in automated runs: fullscreen takes over the
  monitor.

## Skill suggestions

Keep `SKILL_SUGGESTIONS.md` up to date: at the start of a session list
`~/.claude/skills/` and move newly installed skills to "Already installed";
add or sharpen an entry (kebab-case name, one paragraph, a "Why") whenever a
task would have gone better with a missing skill. Mention changes in one line.

## Layout

```text
CMakeLists.txt, CMakePresets.json   project, GameLib pin, presets, the smoke run
src/game/   rules -> GameLib::core only
            rules.*          numbers, the walk/run/ice tuning, Input and its text form
            levels.*         LevelDef, segments joined into areas, the shared goal and arena
            levels_w1..w4.cpp, levels_castle.cpp   the 21 levels as text segments
            session.*        one attempt: hero, blocks, items, coins, pipes, platforms,
                             checkpoint, goal, timer, fireballs, events
            enemies.cpp      walkers, shells, hoppers, fliers, plants, spikies; stomps
            boss.cpp         the Brute (fortresses) and the King (castle)
            overworld.*      the four world maps, open paths (floodFill), routes
            demo_bot.*       the demo player (looks ahead on a copy of the session)
src/app/    presentation -> GameLib::app, ui, fx, ai
            bounder_game.*   the Game: title + demo, map, levels, cards, pause, game over, ending
            view.*           the level: camera, parallax, tiles, furniture, actors, hero
            map_view.*       the overworld drawing
            effects.*        dust, shards, coin pops, rings, sparks, popups, flash, shake
            sounds.*         synthesized effects and the eleven tunes (+ hurry-up takes)
            profile.*        bounder.ini (settings, campaign, map position, run, bests)
            palette.*        a core::Palette per theme
src/main.cpp                AppConfig and runMain
shaders/    tile (every tile kind), hero, enemy, item, scenery, sky, bushes, map
docs/GAMELIB_REVISION.md    the GameLib commit each change was validated with
```

## Level text

Levels are written as segments of rows joined left to right (`levels.hpp`
lists every character). Rules of thumb from the controller's numbers: a
standing jump rises 4.25 tiles (a full-speed run 5.25), so a ledge 3 tiles
up is easy and 4 is the most; a running jump clears about 7 tiles, a walking
one 4. Ice keeps its speed (slow to stop) but lifts are not icy. Each level
has three star coins ('1' '2' '3'), a checkpoint 'F' and a goal 'G' or a
boss arena ('z' gate, 'Z' boss). Bonus rooms are reached by the k-th 'E'
pipe and return to the k-th 'O' pipe.

## Developer aids

- `BOUNDER_START_LEVEL=N` (0-20): PLAY goes straight into level N;
  `BOUNDER_START_COLUMN=C` starts it at column C.
- `BOUNDER_REPLAY=<file>`: a recording (`core::InputRecording` text, the
  four-character inputs of `rules.hpp`) drives the level started with
  `BOUNDER_START_LEVEL`, to watch a proven route and the ending.
  These are GameLib's `app::readDevStart("BOUNDER")`.
- `--keep-running` (GameLib's self-test switch): the game keeps running
  without focus, for screenshot scripts that drive a background window.
- Every level is proven finishable (goal and star coins) by a beam search
  over the real `Session` kept outside the repository; tall levels need
  waypoints for their lifts.
- F3 shows hitboxes and the hero's state.

## Commands

```powershell
cmake --preset debug           # configure (fetches GameLib from GitHub at the pinned commit)
cmake --build --preset debug
ctest --preset debug           # the smoke run (validation layer required)
build/debug/bin/bounder.exe    # --demo: the demo bot plays world 1 full screen
```
